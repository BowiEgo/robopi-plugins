# 003 问答区域设计：引用/命中展示与模式切换

> 状态：设计（未实施）| 2026-08-31
> 相关：002-retrieval-priority.md（检索链路的服务端实现）

## 1. 核心结论

- **零宿主侵入**：所有展示位基于既有插件体系（custom 消息 + messageRenderer + slot）；
- **不自动切换模式**：采用"显式会话级状态 + 常驻工具 + input 钩子注入"，避免隐式行为与 wrapper 重建。

## 2. 展示需求 → 零侵入机制映射

| 展示内容 | 机制（已存在） | 宿主改动 |
|---|---|---|
| 检索卡片（范围/命中/置信/耗时） | custom 消息 + `registerMessageRenderer` | 无 |
| 模式徽标 + 开关 | chat-toolbar slot | 无 |
| 检索详情联动面板 | side 模式工作区视图（规划中） | 无 |
| 回答来源引用 | toolResult 消息（宿主已渲染） | 无 |

## 3. 三层展示设计

### 第 1 层：消息流检索卡片

```
[用户] 我们的报销流程是什么？
[📚 知识库检索]                        ← custom message（服务端扩展注入）
  检索范围: 全部文档库（12 个源）
  命中 3 条:
    · 财务制度/报销流程.md   置信 0.92
    · 财务制度/差旅标准.md   置信 0.78
  耗时 230ms
[Agent] 根据《报销流程.md》……（引用来源标注）
```

服务端扩展在 `input` 钩子检索后 `pi.sendMessage({ customType: "kb-search", ... })`；浏览器插件渲染器展示。

### 第 2 层：工作区联动面板（side 右栏）

- 当前会话问题列表（input 事件记录）
- 点选问题 → 完整检索记录：query、检索范围快照、Top-k 详情、命中是否被回答引用（检索日志关联）
- 「知识库问答模式」toggle（显式、可见）

### 第 3 层：检索范围控制

- 范围选择（全部/某文档库/Wiki 空间）放工作区面板；chat-toolbar 只放模式徽标
- 范围随检索记录进日志 → 评估模块分析"哪个范围命中率低"

## 4. 模式切换策略

### 为什么不"打开面板自动切换"

| 顾虑 | 分析 |
|---|---|
| 隐式行为变化 | 用户可能只是浏览文档，会话突然改变行为——意外感 |
| wrapper 重建风险 | 模式=切工具集会触发 setRpcSessionTools 跨预设边界**重建 wrapper**（已知机制），可能中断会话 |
| 模式≠检索 | 强制注入可以不依赖工具集（input 钩子按标志执行），工具保持默认集 |

### 推荐设计

```
模式状态：会话级显式标志
  - 打开知识库面板 → 显示"未启用问答模式"提示条 + 一键启用（非静默自动）
  - 启用后 → chat-toolbar 显示 📚 徽标；面板记住偏好
强制注入：input 钩子按标志执行（不切工具集 → 不重建 wrapper）
工具注册：search_knowledge_base 常驻（插件安装即注册），模式只控制"是否自动注入"
```

## 5. 完整链路（零侵入架构）

```
浏览器知识库插件（side 工作区）
  ├─ 文档/Wiki/图谱编辑 UI
  ├─ 检索详情联动面板 + 模式开关
  ├─ registerMessageRenderer("kb-search")
  └─ chat-toolbar slot 模式徽标
        │ API
服务端
  ├─ @core/kb-search（Cordis 插件）
  │    ├─ 检索服务（读数据目录）
  │    ├─ 检索日志（供评估模块）
  │    └─ 模式状态存取
  └─ pi 扩展（随 kb 插件安装）
       ├─ registerTool("search_knowledge_base")
       ├─ input 钩子：按模式 → 检索 → sendMessage("kb-search") + context 注入
       └─ tool_call 钩子：日志 + 无结果门控
```

## 6. 宿主侵入边界

| 需求 | 是否侵入 |
|---|---|
| 检索卡片/引用/徽标/联动面板 | 零侵入 |
| 完全自定义问答界面（不要 ChatWindow） | full 视图自建问答 UI，仍零侵入 |
| 消息流内联折叠详情等深度 UI | messageRenderer 实现，零侵入 |
| 修改宿主消息结构（元数据字段） | 侵入（不推荐，custom 消息已够） |

## 7. 实施顺序建议

1. 模式状态 + 检索链路（纯服务端）；
2. 检索卡片渲染（扩展 sendMessage + 插件 messageRenderer）——先验证零侵入链路；
3. 工作区面板联动（side 视图内详情 + 模式开关）；
4. 引用溯源强化（工具返回结构化来源）。
